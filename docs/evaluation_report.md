### Interpretation

- **The templated subset is optimistic.** It was generated from phrasings that overlap with the rule lexicon, so rules-v2's score there mostly confirms the grammar and the lexicon agree. The hand-written subset is the more honest estimate of generalization, and it is still small (35 items), so its exact-match rate has a wide confidence interval.
- **rules-v2's remaining failures are structural**, not lexical: OR-semantics over drugs, histology given in parentheses, negation scope crossing a conjunction ('never received X and are Y'), an unrepresentable criterion leaking into a real one ('excluding pregnant women' → exclusion of women), and the bare `>= 18` form without the word 'age'. These are the cases an LLM extractor is expected to handle better — and the reason the system validates any extractor's output against the same allowlists.
- **Hallucination rate** is measured with an independent alias list: it detects criteria with no surface evidence in the request. It cannot detect a semantically wrong mapping (that shows up as missed/spurious concepts instead). For rule-based extractors it is near zero by construction; the metric exists for LLM extractors.
- **The LLM extractor was not benchmarked** in the build environment (no API key). It is implemented (`backend/cliniq/extraction/llm.py`, schema-constrained tool output, one repair round, no silent fallback) and unit-tested with a fake client. Run `cliniq eval --suite extraction --extractor llm` with `ANTHROPIC_API_KEY` set to add it to this report.

## 2. Evidence retrieval (36 answerable + 6 unanswerable queries)

Corpus: 28 synthetic trial eligibility documents (generated, with varied phrasings) + 14 authored reference notes; 99 chunks. Relevance is document-level and derived from each document's concept tags.

| Mode | Recall@1 | Recall@3 | Recall@5 | Recall@10 | MRR | Abstention precision | Abstention recall | p95 latency |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| bm25 | 0.251 | 0.614 | 0.747 | 0.881 | 0.954 | 0.75 | 1.0 | 6.439 ms |
| dense | 0.251 | 0.612 | 0.745 | 0.878 | 0.954 | 0.6667 | 0.6667 | 7.684 ms |
| hybrid | 0.241 | 0.621 | 0.756 | 0.879 | 0.940 | 0.6667 | 0.6667 | 7.716 ms |

- Recall@1 is low by construction: most queries have 3–10 relevant documents, so one result can recover at most a fraction of them. MRR shows the first relevant document is almost always ranked first.
- BM25 and the local LSA embedder reach similar aggregate scores on this small corpus even though their rankings differ on 40 of 42 queries; hybrid fusion gives a marginal gain at Recall@3–5 and a small loss in MRR. With a corpus this small and synthetic, the honest conclusion is that **no retriever is clearly better**; a neural embedder and a larger, real corpus are needed to make that comparison meaningful.
- Unanswerable-query abstention uses a fixed, pre-set rule (best passage covers < 50% of query terms and cosine < 0.45); thresholds were not tuned on this benchmark.

## Reproducing

```bash
cliniq bootstrap          # same seed → byte-identical dataset
cliniq eval               # writes eval/reports/*.json and ops.eval_runs
python scripts/make_eval_report.py
```

CI enforces regression floors from `eval/thresholds.json` (see `backend/tests/test_extraction_and_eval.py`).
